# 历史剪贴板 Clipboard History

一款常驻系统托盘的 Windows 剪贴板历史管理工具：**找得回、粘得准、不丢数据，历史只保存在本机。**

## 项目简介

后台自动记录复制过的文字和图片，按 `Alt+V` 随时呼出，搜索、筛选、预览，再一键回贴到原来的窗口。

这是一个由我独立负责产品的项目：需求定义、方案取舍、迭代规划和验收由我完成，代码由 [Claude Code](https://claude.ai/code) 根据需求文档与验收标准生成。我自己在用，也分享给了身边的多位同事，**根据使用反馈持续迭代**，目前版本为 v1.2.0。

## 产品目标与设计取舍

目标只有一句话：**快速找回复制过的内容，并准确、可控地粘贴到目标位置。**
围绕它，v1.2 做了这几类取舍：

**1. 粘贴要可信赖，宁可降级也不乱发按键**
自动粘贴前会校验目标窗口、所属进程、前台焦点和剪贴板版本。任何一项对不上，就取消发送按键，退回"只复制"并提示手动粘贴。界面上只写"已发送粘贴操作"，因为我无法保证所有目标应用都收到了，所以不写"粘贴成功"。

**2. 凡是可能丢数据的操作，都要有保护**

| 操作 | 保护方式 |
|------|----------|
| 缩短保留期限 | 先显示将被删除的条数，确认后才生效 |
| 搜索 / 类型 / 时间筛选 | 只改变显示，不删除任何数据 |
| 单条删除 | 10 秒内可撤销 |
| 清空历史 | 二次确认，可选择是否包含收藏 |
| 收藏 | 不参与过期清理和容量清理 |

**3. 隐私默认保守**
数据只存本地、不联网、不上传。可以一键暂停记录，可以按进程名排除应用（如密码管理器）。开机自启默认关闭，错误日志不记录剪贴板正文。

**4. 范围克制**
暂不做云同步、OCR、AI 改写，先把基础体验做扎实。

## 功能

| 类别 | 说明 |
|------|------|
| 自动记录 | 监听系统剪贴板变化，记录文字与图片；相同内容去重，只更新最近使用时间；工具自己回贴的内容不会产生新记录 |
| 检索 | 实时搜索并高亮关键词；全部 / 文字 / 图片 / 收藏筛选；独立的时间范围筛选 |
| 预览 | 完整文字预览；图片支持适应窗口 / 100% / 200% 查看；图片保存原图，列表只加载缩略图 |
| 使用 | 预览、复制、粘贴三个动作分开；点击记录时的默认动作可在设置里选择 |
| 键盘操作 | `↑` `↓` 选择，`Enter` 粘贴，`Ctrl+Shift+C` 只复制，`Space` 预览，`Esc` 隐藏 |
| 窗口 | 无边框圆角窗口，可拖动、可四边四角缩放，记住位置和大小；"保持显示"开启后窗口置顶且不自动隐藏，仍可拖动 |
| 全局快捷键 | 默认 `Alt+V` 呼出 / 隐藏，可在设置中修改，冲突时有提示 |
| 大量历史 | 每页 60 条，可继续加载全部历史；显示总数、匹配数、已加载数；新记录进来时保持当前滚动位置 |
| 长期运行 | 保留期限 1 / 3 / 5 / 7 / 30 天（默认 3 天）；条数与存储容量上限（默认 2000 条 / 512 MB）；定时清理与数据库空间回收；设置原子保存 |
| 隐私 | 暂停 / 恢复记录（托盘菜单也可操作）；从运行中的应用选择排除项，或输入完整进程名 |
| 其他 | 单实例（重复启动会唤起已有窗口）；可选开机自启；首次使用指引 |

## 快速开始

环境：Windows 10 / 11，Python 3.14。

```bash
pip install PySide6
python main.py
```

启动后图标会出现在系统托盘，像平时一样 `Ctrl+C` 复制即可，按 `Alt+V` 呼出历史。

打包为免安装的单文件 exe：

```bash
pip install pyinstaller
pyinstaller ClipboardHistory.spec
```

使用细节见 [使用说明](docs/user-guide.md)。程序会在 exe（或 `main.py`）同目录下创建 `data/` 文件夹保存历史，请放在有写入权限的位置。

### 关键决策与踩坑

| 问题 | 处理 | 原因 |
|------|------|------|
| Electron 28 / 35 / 42 均无法正确解析 `require('electron')`，约 1 小时无果 | 止损，改用 Python + PySide6 | 继续排查的成本高于换方案 |
| `Alt+V` 热键不生效 | 重写 `nativeEvent`，直接捕获 Windows 的 `WM_HOTKEY` 消息 | 只注册了 `RegisterHotKey`，没有监听消息 |
| 图片保存报错 | 改用 Qt 的 `QBuffer` | `QPixmap.save()` 不接受 Python `BytesIO` |
| v1.0 只存 200px 缩略图，图片无法原样回贴 | v1.2 原图与缩略图分开存储，并做数据库迁移 | 旧图缺失的像素无法补回，界面上明确标注限制 |
| 切换"保持显示"后 `Alt+V` 失效 | 不再用 `setWindowFlags` 切换，只改行为不改窗口标志 | 改窗口标志会重建原生窗口，热键绑定在旧句柄上 |
| 圆角窗口阴影区接不到缩放事件 | 阴影区铺一层 alpha=1 的底 | Windows 分层窗口里完全透明的像素会被鼠标穿透 |

## 测试与已知限制

`tests/test_iteration.py` 共 16 项回归，使用临时数据库和合成数据，并以离屏渲染检查布局，覆盖：原图保真、旧数据迁移、去重、全部记录可访问且筛选不删数据、收藏保护与删除撤销、暂停与排除应用、目标失效时不发送按键、自身回贴不入库、设置原子保存、滚动位置保持、容量清理、空状态与最小窗口渲染等。

```bash
python tests/test_iteration.py
```

**尚未做完的验证**（不把它们当成已测试）：

- 微信、飞书等具体目标应用对自动粘贴的接收情况
- 真机鼠标拖动、多屏与高分屏缩放
- 长时间连续运行

**已知限制**：

- 原图保存从 v1.2 起生效，旧版本留下的图片只有 200px 缩略图
- 不同权限等级的窗口、远程桌面和应用自身限制，仍可能让自动粘贴失效，此时请手动 `Ctrl+V`
- 历史保存在本地 `data/` 中，未加密；分享程序时只分享 exe 和使用说明，不要带上个人的 `data/` 文件夹
- 更新方式为手动替换 exe，没有联网自动更新

## 技术栈

- **Python 3.14** + **PySide6 6.11**（Qt 6）：界面、托盘、剪贴板监听
- **SQLite（WAL 模式）**：本地存储，增量空间回收，旧库自动迁移
- **Win32 API（ctypes）**：全局热键、前台窗口与进程检测、剪贴板序列号、模拟按键
- **PyInstaller**：打包为免安装的单文件 exe
